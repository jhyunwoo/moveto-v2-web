# GEMINI.md - Moveto V2 Project Overview

## Project Overview

**Moveto V2** is a high-performance, web-based file-sharing service designed for quick and secure file transfers without requiring a complex login process (though authentication is available). It is built with a modern tech stack focused on speed, scalability, and a seamless user experience.

### Core Architecture
- **Framework:** [Next.js 15](https://nextjs.org/) (App Router) with [React 19](https://react.dev/).
- **Styling:** [Tailwind CSS 4](https://tailwindcss.com/) for utility-first styling.
- **Database:** [PostgreSQL](https://www.postgresql.org/) managed via [Drizzle ORM](https://orm.drizzle.team/).
- **Storage:** [Cloudflare R2](https://www.cloudflare.com/developer-platform/r2/) (S3-compatible) for file storage.
- **Authentication:** [Better Auth](https://www.better-auth.com/) supporting Passkeys, GitHub, and Kakao OAuth.
- **File Uploads:** [Uppy](https://uppy.io/) integrated within a **Web Worker** (`lib/worker/file-upload-worker.ts`) to handle heavy upload tasks without blocking the main UI thread. Supports standard and multipart uploads for large files.
- **State Management:** [Zustand](https://zustand-demo.pmnd.rs/) for client-side state.
- **Animations:** [Motion](https://motion.dev/) (Framer Motion v12) for smooth UI transitions.

### Key Logic & Flow
1. **Share Creation:** When a user selects files, the client calls `POST /api/share` to create a record in the `share` table.
2. **File Upload:** The Web Worker uses Uppy to upload files directly to R2 using presigned URLs or multipart upload API routes (`/api/s3/*`).
3. **Access Code:** After a successful upload, the client calls `PUT /api/share/[shareId]/code` to generate a human-friendly access code (e.g., "fast-blue-cat") using a combination of adjectives and nouns from the DB.
4. **Expiration:** Shares are time-limited, and the expiration is set during the code generation phase.

## Building and Running

### Prerequisites
- [pnpm](https://pnpm.io/) (v10.x recommended)
- PostgreSQL database
- Cloudflare R2 Bucket and API keys

### Installation
```bash
pnpm install
```

### Environment Variables
Create a `.env` file with the following keys:
- `DATABASE_URL`: Postgres connection string
- `R2_ENDPOINT`, `R2_ACCESS_KEY`, `R2_SECRET_KEY`, `R2_BUCKET`: Cloudflare R2 credentials
- `BETTER_AUTH_SECRET` / `AUTH_SECRET`: Secret for Better Auth
- `AUTH_GITHUB_ID`, `AUTH_GITHUB_SECRET`: GitHub OAuth credentials
- `AUTH_KAKAO_ID`, `AUTH_KAKAO_SECRET`: Kakao OAuth credentials
- `NEXT_PUBLIC_SITE_URL`: The public URL of the application
- `BETTER_AUTH_URL` / `AUTH_URL`: The URL for authentication callback

### Development
```bash
pnpm dev
```

### Database Management
- Generate migrations: `pnpm db:generate`
- Apply migrations: `pnpm db:migrate`
- Push schema directly (dev): `pnpm db:push`
- Drizzle Studio: `pnpm db:studio`

### Production Build
```bash
pnpm build
pnpm start
```

## Development Conventions

### Coding Style
- **TypeScript:** Use strict typing. Definitions are mostly found in `lib/types.ts` and `db/schema.ts`.
- **Components:** Functional components with React 19. Prefer `use client` only when necessary.
- **Hooks:** Custom hooks are located in `lib/hooks/` (e.g., `use-file-upload.ts`, `use-drag-and-drop-file.ts`).
- **State:** Use Zustand stores in `lib/stores/`.

### File Uploads
- All file upload logic MUST be handled via the Web Worker (`lib/worker/file-upload-worker.ts`) to maintain UI responsiveness.
- Large files SHOULD use the multipart upload routes.

### UI/UX
- Use Tailwind CSS 4 for all styling.
- Animations should use `motion` from the `motion` package.
- The app is mobile-first and includes PWA features like splash screens for iOS.

### Database
- Use Drizzle ORM for all database interactions.
- Schema is defined in `db/schema.ts`.
- Share codes are generated by combining `nouns` and `adjectives` tables. Ensure these tables are populated.

### API Routes
- Route handlers are located in `app/api/`.
- Use `getSession()` from `@/auth` to protect routes that require authentication.
- All file-related API routes should follow the `/api/s3/` or `/api/share/` patterns.
